# Telegram Forwarder

ربات مدیریت انتقال پیام از یک کانال تلگرام به کانال دیگر، با انتقال دستی و خودکار، بازنویسی و پالایش متن با AI، صف تصمیم‌گیری مدیر و ذخیره وضعیت در SQLite.

کنترل ربات از طریق دکمه‌های تلگرام انجام می‌شود. دریافت پیام‌های کانال و ارسال به مقصد با **حساب کاربری Telethon** انجام می‌شود؛ ربات Bot API نقش پنل مدیریت را دارد. پیام‌های معمولی پس از پردازش متن/کپشن و افزودن امضا، به‌صورت پیام تازه بازنشر می‌شوند؛ بنابراین نباید برای همه پیام‌ها انتظار برچسب «Forwarded from» داشت. نظرسنجی مسیر فوروارد جدا دارد.

<a id="features"></a>
## امکانات و محدودیت‌ها

- انتخاب مبدأ و مقصد، انتقال یک بازه یا فهرست مشخصی از شناسه پیام‌ها و دریافت خودکار پیام‌های جدید.
- مشاهده پیشرفت، درخواست توقف، ادامه عملیات متوقف‌شده و تلاش مجدد برای خطاها از رابط ربات.
- ثبت نتایج و جلوگیری از ارسال مجدد پیام موفق به همان مقصد، بر اساس مبدأ، شناسه پیام و مقصد.
- تنظیم امضا و حذف یا جایگزینی آیدی‌های داخل متن.
- تنظیم سرویس AI، مدل و کلید از چت خصوصی مدیر.
- گارد زمینه‌محور با بازنویسی، بررسی حفظ معنا، تلاش محدود برای اصلاح و ارجاع موارد حل‌نشده به مدیر.
- تغییر حساسیت موضوعات و ورود/خروج تنظیمات کامل گارد در قالب JSON.
- نگهداری درخواست‌های بررسی، پیش‌نویس‌ها، کانال‌ها و تنظیمات در دیتابیس.

محدوده پیاده‌سازی فعلی:

| موضوع | رفتار فعلی |
|---|---|
| متن و کپشن | ورودی اصلی گارد هستند؛ HTML تلگرام پردازش و پاک‌سازی می‌شود |
| عکس، صدا و ویدئو | رسانه همراه پیام منتقل می‌شود؛ تحلیل تصویری، OCR و تبدیل صدا به متن در گارد پیاده نشده است |
| آلبوم | پیام‌ها جدا پردازش می‌شوند؛ حفظ گروه‌بندی آلبوم در مقصد تضمین نشده است |
| نظرسنجی | با AI روشن نیازمند تصمیم مدیر است؛ بازنویسی یا ویرایش نظرسنجی پشتیبانی نمی‌شود |
| محتوای محافظت‌شده | اگر تلگرام انتقال را رد کند، خطا ثبت می‌شود؛ ارسال موفق تضمین نمی‌شود |
| قطعی و Restart | تنظیمات و سوابق باقی می‌مانند، اما صف دائمی برای تضمین دریافت تمام پیام‌های زمان قطعی وجود ندارد |
| ادامه عملیات | وضعیت Job ذخیره می‌شود؛ ادامه خودکار همه Jobهای در حال اجرا پس از Restart تضمین نشده است |
| اجرای هم‌زمان | فقط یک نمونه از برنامه اجرا شود؛ قفل پیام درون همان پردازش است |
| خاموش بودن AI | گارد محتوایی AI اجرا نمی‌شود؛ با روشن بودن AI و خطای سرویس، متن اصلی خودکار منتشر نمی‌شود |

جلوگیری از تکرار به دیتابیس وابسته است. حذف دیتابیس، سابقه ارسال را هم حذف می‌کند. در صورت قطع ارتباط درست هنگام ارسال، ممکن است نتیجه ارسال نامشخص باشد؛ این وضعیت را با بررسی مقصد حل کنید، نه با تلاش مجدد بدون بررسی.

<a id="requirements"></a>
## پیش‌نیازها و دسترسی‌ها

برای هماهنگی با Dockerfile، **Python 3.12** پیشنهاد می‌شود. پروژه از قابلیت‌های Python 3.12 استفاده می‌کند. اتصال خروجی به Telegram Bot API، شبکه MTProto تلگرام و در صورت فعال‌سازی AI، سرویس مدل لازم است.

| مقدار | کاربرد |
|---|---|
| `BOT_TOKEN` | توکن ربات پنل مدیریت |
| `API_ID` و `API_HASH` | مشخصات برنامه تلگرام برای اتصال Telethon |
| `ADMIN_IDS` | شناسه عددی حساب‌های مجاز به مدیریت ربات |
| نشست Telethon | مجوز ورود حساب کاربری که پیام‌ها را می‌خواند و ارسال می‌کند |

### دریافت اعتبارنامه‌ها

۱. در تلگرام به `@BotFather` پیام بدهید، `/newbot` را اجرا و توکن ربات را دریافت کنید.
۲. در `my.telegram.org` وارد بخش **API development tools** شوید، برنامه بسازید و `api_id` و `api_hash` را بردارید.
۳. شناسه عددی حساب مدیر را با ابزار معتبر نمایش شناسه حساب پیدا کنید؛ شماره تلفن، `@username` و شناسه کانال جایگزین آن نیستند. برای چند مدیر از کاما استفاده کنید.

**دسترسی کانال‌ها مربوط به حساب کاربری واردشده در Telethon است.** برای مبدأ خصوصی، این حساب باید عضو باشد؛ برای دریافت خودکار نیز حساب را عضو مبدأ کنید. برای انتشار در کانال مقصد، حساب باید مجوز انتشار پیام داشته باشد. اضافه کردن ربات مدیریتی به‌عنوان ادمین مبدأ، جای ورود و دسترسی حساب کاربری را نمی‌گیرد.

<a id="local-setup"></a>
## نصب و اجرای محلی

دستورات را از ریشه پروژه، یعنی پوشه حاوی `main.py`، اجرا کنید. برای نصب تازه از فایل نمونه کپی بگیرید؛ `.env` موجود را بازنویسی نکنید.

### ویندوز و PowerShell

```powershell
cd "D:\Habib\mtb\New folder\telegram-forwarder"
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
if (-not (Test-Path -LiteralPath .env)) { Copy-Item .env.example .env }
notepad .env
```

مسیر پروژه را در صورت نیاز عوض کنید. فعال کردن `Activate.ps1` لازم نیست؛ استفاده مستقیم از Python محیط مجازی از مشکل Execution Policy جلوگیری می‌کند.

### لینوکس و macOS

پس از آماده بودن Python 3.12 و پشتیبانی venv:

```bash
cd /path/to/telegram-forwarder
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
test -f .env || cp .env.example .env
```

فایل `.env` را با ویرایشگر متن باز کنید. اگر `python3.12` یا venv در دسترس نیست، بسته/مسیر مناسب سیستم یا هاست خود را آماده کنید؛ نام بسته نصب در همه توزیع‌ها یکسان نیست.

### حداقل تنظیمات نصب اولیه

اعتبارنامه‌های زیر نمونه‌اند و باید جایگزین شوند:

```dotenv
BOT_TOKEN=REPLACE_WITH_BOT_TOKEN
API_ID=123456
API_HASH=REPLACE_WITH_API_HASH
ADMIN_IDS=123456789
DATABASE_URL=sqlite:///data/forwarder.db
TELETHON_SESSION=sessions/forwarder_session
TELETHON_STRING_SESSION=
LOG_LEVEL=INFO
LOG_TO_FILE=true
FORWARD_DELAY=1.5
PROGRESS_UPDATE_INTERVAL=3
PROXY_ENABLED=false
AI_ENABLED=false
AI_API_KEY=
```

**فایل `.env.example` فعلی پروکسی محلی و AI را روشن دارد و کلید آن نمونه است.** صرف کپی فایل برای راه‌اندازی کافی نیست: اگر پروکسی ندارید، آن را خاموش کنید؛ تا ثبت کلید واقعی و تنظیم AI نیز `AI_ENABLED=false` بگذارید. در این مرحله انتقال خودکار را روشن نکنید، چون AI خاموش به معنی نبود پالایش محتوایی است.

اگر تلگرام روی کامپیوتر بدون پروکسی وصل نمی‌شود، مقادیر `PROXY_TYPE`، `PROXY_HOST` و `PROXY_PORT` را برای پروکسی واقعاً فعال خود تنظیم و `PROXY_ENABLED=true` کنید. مقدار نمونه `127.0.0.1:12334` تضمین وجود سرویس پروکسی نیست. این تنظیمات مربوط به اتصال تلگرام‌اند؛ تنظیم اختصاصی پروکسی سرویس AI از منوی ربات وجود ندارد.

### اجرای برنامه

ویندوز:

```powershell
.\.venv\Scripts\python.exe -u main.py
```

لینوکس/macOS:

```bash
.venv/bin/python -u main.py
```

در اولین ورود تعاملی، شماره حساب با کد کشور، کد ورود تلگرام و در صورت فعال بودن، رمز دومرحله‌ای درخواست می‌شود. نشست در `sessions/forwarder_session.session` ذخیره می‌شود. برای خروج عادی `Ctrl+C` بزنید و تا پایان برنامه منتظر بمانید.

<a id="session"></a>
## نشست تلگرام و انتقال به سرور

سرور بدون ترمینال نباید منتظر کد ورود باشد. ابتدا روی کامپیوتر، با اعتبارنامه‌ها و اتصال درست، نشست را بسازید. قبل از صدور نشست، اجرای دیگر برنامه را متوقف کنید:

```powershell
.\.venv\Scripts\python.exe -m scripts.export_session
```

در لینوکس:

```bash
.venv/bin/python -m scripts.export_session
```

خروجی در `sessions/railway-session.txt` ذخیره می‌شود. نام فایل به معنی محدود بودن آن به Railway نیست؛ برای cPanel هم قابل استفاده است. محتوای کامل آن را در `TELETHON_STRING_SESSION` سرور قرار دهید. اسکریپت خروجی موجود را بازنویسی نمی‌کند؛ فایل قبلی معتبر را استفاده یا پیش از صدور تازه به محل خصوصی پشتیبان منتقل کنید.

رشته نشست، کلید API و توکن را در Git، تصویر، لاگ یا پیام پشتیبانی منتشر نکنید. نشست رشته‌ای فقط وقتی فایل نشست هنوز کلید ورود ندارد وارد آن می‌شود؛ تغییر Variable به‌تنهایی حساب یک نشست موجود را عوض نمی‌کند. برای تعویض نشست، برنامه را متوقف، پشتیبان تهیه و فقط فایل نشست قبلی و فایل‌های جانبی همان نشست را کنار بگذارید؛ دیتابیس تنظیمات را حذف نکنید.

<a id="usage"></a>
## کار با ربات

### اولین انتقال

۱. با حسابی که شناسه آن در `ADMIN_IDS` است، در چت خصوصی ربات `/start` بفرستید.
۲. مبدأ را با `@channel` یا شناسه عددی مناسب تعیین و مشخصات نمایش‌داده‌شده را تأیید کنید.
۳. مقصد را تعیین کنید و دسترسی انتشار حساب Telethon را بررسی کنید. ابتدا مقصد آزمایشی انتخاب کنید.
۴. AI و حساسیت‌های گارد را مطابق بخش‌های بعد تنظیم کنید.
۵. از منوی انتقال، بازه یا لیست شناسه پیام‌ها را انتخاب کنید. مثلاً در لینک `https://t.me/example/134`، عدد `134` شناسه پیام است؛ با شناسه کانال تفاوت دارد.
۶. خلاصه مبدأ، مقصد و انتخاب پیام‌ها را ببینید و عملیات را تأیید کنید.
۷. پیشرفت و نتیجه را بررسی کنید؛ پیام کنارگذاشته‌شده، تکراری، نیازمند بررسی و خطای ارسال یک معنی ندارند.

### انتقال خودکار و مدیریت عملیات

Auto-Forward برای پیام‌های جدید مبدأ است. بعد از روشن کردن، یک پیام تازه آزمایش کنید؛ روشن کردن آن به‌تنهایی آرشیو قبلی را منتقل نمی‌کند. برای بازیابی پیام‌های ازدست‌رفته زمان قطعی، بازه یا لیست شناسه‌ها را دستی انتخاب کنید.

تغییر مبدأ یا مقصد باید شنونده خودکار را با تنظیم جدید هماهنگ کند. درخواست‌های بررسی قبلی **مقصد ثبت‌شده خودشان را حفظ می‌کنند**؛ مقصد هر کارت را قبل از تأیید بخوانید. توقف یک انتقال دستی، لزوماً به معنی خاموش کردن Auto-Forward نیست.

توقف دستی در مرز پردازش پیام‌ها اعمال می‌شود؛ اگر درخواست AI یا انتظار FloodWait در جریان باشد، ممکن است فوری تمام نشود. مسیر انتقال دستی پس از FloodWait به اندازه زمان اعلام‌شده صبر و یک بار دیگر تلاش می‌کند؛ تکرار نامحدود تضمین نشده است.

### دستورهای میان‌بر

| دستور | کاربرد |
|---|---|
| `/start` و `/menu` | داشبورد |
| `/settings` | تنظیمات |
| `/reviews` | درخواست‌های بررسی |
| `/recent` | عملیات اخیر |
| `/stats` | آمار |
| `/help` | راهنما |
| `/cancel` | لغو ورودی/پیش‌نویس تنظیمات جاری و بازگشت؛ توقف عمومی همه انتقال‌ها نیست |

### امضا و آیدی‌ها

در «تنظیمات» می‌توانید امضا را تغییر یا حذف کنید و برای آیدی‌های داخل پیام، حذف یا آیدی جایگزین تعیین کنید. پاک‌سازی آیدی‌ها حتی با AI خاموش نیز انجام می‌شود. با AI روشن و هنگام تأیید دستی، لینک‌ها از متن پردازش‌شده پاک می‌شوند؛ با AI خاموش، حذف عمومی لینک‌ها فعال نیست. امضا بعد از پردازش متن اضافه می‌شود و خود آن از مسیر بررسی AI پیام عبور نمی‌کند؛ آن را آگاهانه تنظیم کنید.

<a id="ai"></a>
## تنظیم سرویس AI

در چت خصوصی مدیر: **تنظیمات ← تنظیمات هوش مصنوعی**.

۱. ابتدا آدرس سرویس را ثبت کنید؛ باید endpoint کامل HTTPS سازگار با Chat Completions باشد. نمونه: `https://api.openai.com/v1/chat/completions`. آدرس را متن ساده بفرستید، نه لینک Markdown.
۲. کلید API واقعی همان سرویس را ثبت کنید؛ ربات تلاش می‌کند پیام حاوی کلید را حذف کند. اگر حذف ممکن نبود، خودتان پیام را پاک کنید.
۳. نام مدل قابل استفاده در حساب سرویس‌دهنده را وارد کنید. نام مدل نمونه، تضمین پشتیبانی سرویس دیگر نیست.
۴. AI را روشن و با پیام آزمایشی بررسی کنید.

تغییر آدرس سرویس، کلید قبلی را پاک و AI را خاموش می‌کند؛ پس ترتیب «آدرس ← کلید ← مدل ← فعال‌سازی» را رعایت کنید. مدل، آدرس و کلید در دیتابیس ذخیره می‌شوند؛ تنظیمات ثبت‌شده بر پیش‌فرض env اولویت دارند.

متن/کپشن، زمینه فشرده مرتبط و در مرحله بررسی، متن اصلی و پیش‌نویس برای سرویس AI تنظیم‌شده ارسال می‌شوند. کل تاریخچه کانال یا محتوای تصویری/صوتی به‌عنوان ورودی چندرسانه‌ای ارسال نمی‌شود.

<a id="guard"></a>
## گارد چندمرحله‌ای چگونه تصمیم می‌گیرد؟

۱. تنظیمات جاری برای این پردازش خوانده می‌شوند؛ مراحل آن پیام یک نسخه ثابت از سیاست و محدودیت‌ها دارند.
۲. طول ورودی، نرمال‌سازی، زمینه و کش بررسی می‌شوند. در سیاست پایه، بعضی موارد واضح محلی تصمیم‌گیری می‌شوند؛ نامشخص بودن یا سیاست اختصاصی می‌تواند نیاز به AI ایجاد کند.
۳. مدل متن را تحلیل می‌کند. ابهام یا نیاز به بازنگری، فرصت بازنویسی خودکار دارد؛ هر پیام سیاسی مستقیماً به مدیر ارجاع نمی‌شود.
۴. پیشنهاد حذف مدل، یک ارزیابی مستقل دیگر دارد. توهین خالصِ واضح در سیاست محلی پایه ممکن است مستقیماً حذف شود.
۵. متن پیشنهادی برای انتشار پاک‌سازی و با اصل مقایسه می‌شود: حفظ معنا، عدد، نام، نفی، انتساب و رعایت قوانین بررسی می‌شوند.
۶. در صورت امکان، یک تلاش ترمیم و بررسی مجدد انجام می‌شود. ابهام حل‌نشده، پاسخ نامعتبر، پایان بودجه یا خطای سرویس به بررسی می‌رود.

| تصمیم | نتیجه |
|---|---|
| `PUBLISH` | انتشار متن تأییدشده یا بازنویسی معتبر |
| `DROP` | پیام به مقصد ارسال نمی‌شود؛ پیام مبدأ حذف نمی‌شود |
| `REVIEW` | انتشار متوقف و درخواست تصمیم مدیر ثبت می‌شود |

سیاسی بودن موضوع، نقل‌قول خبری یا وجود یک واژه به‌تنهایی نباید جای تحلیل زمینه را بگیرد. بازنویسی مجاز باید معنی و انتساب را حفظ کند؛ ساختن خبر تازه یا معکوس کردن ادعا، اصلاح معتبر نیست. با این حال تصمیم مدل بی‌خطا نیست و تست واحد جای ارزیابی کیفیت سرویس واقعی را نمی‌گیرد.

پیش‌فرض‌ها: حداکثر ۴۰۰۰ کاراکتر ورودی، ۱۰۲۴ توکن خروجی هر درخواست، ۶۰ ثانیه برای هر درخواست، ۱۲۰ ثانیه برای کل پردازش، ۶ مرحله و ۸ درخواست. این‌ها سقف‌اند؛ هر پیام الزاماً همه مراحل را طی نمی‌کند. پس از خطاهای متوالی، مدار سرویس برای مدتی متوقف می‌شود تا درخواست‌های پی‌درپی به سرویس ناموفق ارسال نشوند.

<a id="guard-settings"></a>
## تنظیم گارد با دکمه و فایل

مسیر: **تنظیمات ← حساسیت و فایل تنظیمات گارد**.

حساسیت چهار موضوع `political`، `abuse`، `sexual` و `spam` با دکمه قابل تغییر است:

| مقدار فایل | معنی |
|---|---|
| `off` | این موضوع به‌تنهایی علت حذف یا بازنویسی نباشد؛ سایر قواعد برقرارند |
| `standard` | حساسیت معمولی و تحلیل زمینه‌محور |
| `strict` | بررسی دقیق‌تر موضوع و اصلاح موارد ناقض، بدون حذف صرفاً بر اساس کلمه |

### ورود و خروج JSON

۱. «دریافت فایل تنظیمات» را بزنید؛ خروجی تنظیمات واقعی فعلی است.
۲. فایل `guard-settings.json` را با ویرایشگر متن و UTF-8 باز کنید.
۳. حساسیت‌ها، متن فارسی `instructions` و مقادیر `limits` را ویرایش کنید.
۴. «بارگذاری فایل» را بزنید و فایل را به‌صورت Document ارسال کنید.
۵. تفاوت‌ها و نسخه کامل پیشنهادی را ببینید؛ «اعمال تنظیمات» را بزنید یا لغو کنید.

[قالب کامل آماده](docs/guard-settings.example.json) در مخزن موجود است. شکل کلی فایل چنین است؛ این نمایش خلاصه است و برای ارسال باید همه فیلدهای `limits` قالب را نگه دارید:

```text
version       نسخه عددی قالب؛ فعلاً 1
sensitivity   حساسیت چهار موضوع
instructions  قوانین اختصاصی فارسی به‌صورت رشته
limits        تمام محدودیت‌های زمان، مراحل، اطمینان، زمینه و کش
```

مثلاً در فایل کامل، `instructions` می‌تواند این رشته باشد:

```json
"instructions": "نقل‌قول خبر را با انتساب روشن حفظ کن. تحلیل یا نتیجه‌گیری تازه اضافه نکن."
```

حداکثر فایل ۶۴ کیلوبایت و حداکثر متن قوانین ۱۲۰۰۰ کاراکتر است. نسخه نادرست، کلید ناشناخته/تکراری، فایل ناقص، مقدار خارج از بازه و نوع عددی نامعتبر رد می‌شوند؛ تغییری از فایل نامعتبر ذخیره نمی‌شود. JSON کامنت یا کامای اضافه پس از آخرین فیلد نمی‌پذیرد.

تغییرات بدون Restart از پردازش بعدی اعمال می‌شوند. پردازش جاری با تنظیم قبلی تمام می‌شود؛ تاریخچه یا صف بررسی خودکار بازپردازش نمی‌شوند. تأیید قدیمی نمی‌تواند تغییر جدیدتر مدیر دیگر را بازنویسی کند. فایل خروجی کلید API یا نشست ندارد؛ قوانین اختصاصی خودتان هم نباید اطلاعات محرمانه داشته باشند.

فایل گارد جای تنظیمات اتصال، امضا و آیدی‌ها نیست. حفاظت از دستورات مدل، قرارداد خروجی و پاک‌سازی نهایی همچنان برقرارند. توضیح دقیق تمام فیلدها و بازه‌ها در [راهنمای تنظیم گارد](docs/guard-settings.md) آمده است.

<a id="reviews"></a>
## صف بررسی و ویرایش پیام

موارد حل‌نشده با دلیل و مقصد ثابت در صف ثبت و برای مدیر اعلان می‌شوند. `/reviews` آن‌ها را نشان می‌دهد.

| دکمه | رفتار |
|---|---|
| تأیید نسخه فعلی | نسخه فعلی/پیش‌نویس را با پاک‌سازی و امضای جاری ارسال می‌کند؛ تأیید دستی جای تصمیم گارد را می‌گیرد |
| رد پیام | درخواست را رد می‌کند و به مقصد نمی‌فرستد |
| ویرایش | متن جدید شما را به‌عنوان پیش‌نویس نگه می‌دارد؛ هنوز ارسال نمی‌کند |
| بازنویسی با AI | پیش‌نویس معتبر یا پیشنهاد رد می‌سازد؛ پس از آن همچنان تأیید، رد و ویرایش در دسترس‌اند |

**بازنویسی خودکار داخل گارد با دکمه بازنویسی در صف فرق دارد.** گارد می‌تواند بازنویسیِ بررسی‌شده را خودکار منتشر کند؛ اما وقتی درخواست وارد صف تصمیم مدیر شد، دکمه AI فقط پیش‌نویس می‌سازد و به‌تنهایی ارسال نمی‌کند.

اگر پیام مبدأ بعد از ایجاد درخواست عوض شده باشد، تأیید قدیمی معتبر نیست و بررسی تازه لازم است. اگر نتیجه ارسال «نامشخص» باشد، ابتدا کانال مقصد را ببینید؛ بازگرداندن بی‌بررسی به صف ممکن است باعث ارسال تکراری شود. نظرسنجی قابل ویرایش با این مسیر نیست و تأیید آن اصل نظرسنجی را فوروارد می‌کند.

<a id="configuration"></a>
## متغیرهای محیطی و اولویت تنظیمات

فایل‌های نمونه: [محلی](.env.example) و [Railway](.env.railway.example). فایل `.env` از ریشه پروژه خوانده می‌شود؛ متغیر محیطی موجود سیستم بر مقدار متناظر آن اولویت دارد. تغییر تنظیمات پایه معمولاً نیازمند Restart است.

| گروه | متغیرها و کاربرد |
|---|---|
| تلگرام | `BOT_TOKEN`، `API_ID`، `API_HASH`، `ADMIN_IDS` |
| ذخیره‌سازی | `DATABASE_URL` و `TELETHON_SESSION`؛ مسیر نشست بدون پسوند |
| ورود سرور | `TELETHON_STRING_SESSION`؛ برای ساخت نشست مجاز در محیط غیرتعاملی |
| لاگ | `LOG_LEVEL` و `LOG_TO_FILE` |
| انتقال | `FORWARD_DELAY` فاصله ارسال و `PROGRESS_UPDATE_INTERVAL` فاصله اعلان پیشرفت، به ثانیه |
| پروکسی تلگرام | `PROXY_ENABLED`، `PROXY_TYPE`، `PROXY_HOST`، `PROXY_PORT` و در صورت نیاز `PROXY_USERNAME`/`PROXY_PASSWORD` |
| پیش‌فرض اتصال AI | `AI_ENABLED`، `AI_API_KEY`، `AI_BASE_URL`، `AI_MODEL` |
| قوانین اختصاصی اولیه | `AI_GUARDRAILS`؛ خالی یعنی سیاست همراه پروژه |
| پیش‌فرض حدود گارد | متغیرهای `AI_GUARD_*` در فایل نمونه |

پس از ذخیره در ربات:

- تنظیمات سرویس AI بر env متناظر خود اولویت دارند.
- پروفایل گارد ذخیره‌شده، حساسیت‌ها، قوانین اختصاصی و محدودیت‌ها را تعیین می‌کند. تغییر `AI_GUARD_*` در env لزوماً پروفایل ذخیره‌شده را تغییر نمی‌دهد.
- خروجی اولیه پروفایل، قوانین اختصاصی env را هم منعکس می‌کند. پس از ذخیره، خالی کردن `instructions` قوانین اختصاصی را حذف می‌کند؛ سیاست پایه همراه کد باقی می‌ماند.

نام env هر محدودیت، `AI_GUARD_` به‌علاوه نام فیلد با حروف بزرگ است؛ مثلاً `timeout_seconds` برابر `AI_GUARD_TIMEOUT_SECONDS` و `ai_confidence_threshold` برابر `AI_GUARD_AI_CONFIDENCE_THRESHOLD` است.

<a id="troubleshooting"></a>
## لاگ و عیب‌یابی

خروجی کنسول همیشه فعال است. با `LOG_TO_FILE=true`، فایل‌های چرخشی `logs/app.log` و `logs/error.log` ساخته می‌شوند؛ فایل دوم هشدارها و خطاها را نگه می‌دارد. روی Railway معمولاً `false` مناسب است تا لاگ را از پنل ببینید.

هر حدود ۶۰ ثانیه وضعیت اتصال، انتقال خودکار، شمارنده‌ها و AI ثبت می‌شود. شناسه‌های `job_id`، `source_id`، `destination_id` و `msg_id` برای دنبال کردن یک پیام در مراحل مختلف‌اند. شمارنده‌های runtime پس از Restart از نو شروع می‌شوند و با تاریخچه دائمی دیتابیس یکی نیستند.

| لاگ | برداشت درست |
|---|---|
| `telegram_connected=True` | اتصال Telethon برقرار است؛ به‌تنهایی مجوز مقصد یا سلامت AI را ثابت نمی‌کند |
| `stage=analyze/rewrite/verify/repair/drop_audit` | مرحله فعلی گارد |
| `action=PUBLISH/DROP/REVIEW` | تصمیم نهایی درباره آن پیام |
| `cached=True` | استفاده از نتیجه معتبر کش |
| `ai_call_ratio` | تعداد فراخوانی مراحل AI تقسیم بر تعداد پیام‌های پردازش‌شده؛ به دلیل چندمرحله‌ای بودن می‌تواند بزرگ‌تر از ۱ باشد |
| `uncertain` | نتیجه ارسال معلوم نیست؛ قبل از تلاش مجدد مقصد بررسی شود |

### خطاهای رایج

| نشانه | بررسی و اقدام |
|---|---|
| `InvalidToken` | توکن واقعی BotFather را بررسی کنید |
| `/start` پاسخ مدیریتی ندارد | `ADMIN_IDS`، خصوصی بودن چت، توکن و لاگ اتصال را ببینید |
| Timeout ورود تلگرام | شبکه/پروکسی همین میزبان را بررسی کنید؛ timeout AI ارتباطی با ورود ندارد |
| خطای اتصال به `127.0.0.1` | پروکسی محلی روشن نیست یا آدرس کامپیوتر را روی سرور استفاده کرده‌اید |
| `interactive login is unavailable` | نشست را محلی صادر و در تنظیمات سرور قرار دهید |
| `Conflict ... getUpdates` | اجرای دیگر با همین توکن را متوقف کنید؛ تنها یک نمونه اجرا شود |
| `database is locked` | اجرای موازی یا استفاده هم‌زمان از نشست/دیتابیس را بررسی کنید |
| کانال پیدا نمی‌شود | شناسه و دسترسی حساب Telethon، به‌خصوص عضویت مبدأ خصوصی، بررسی شود |
| مقصد اجازه ارسال ندارد | مجوز انتشار حساب کاربری واردشده را اصلاح کنید |
| تنظیمات پس از Deploy پاک می‌شوند | Volume و مسیر دیتابیس را بررسی کنید |
| تغییر env روی AI اثر ندارد | تنظیم ثبت‌شده در ربات اولویت دارد؛ از منوی مربوط تغییر دهید |
| AI خطای 401/403 می‌دهد | کلید و دسترسی حساب سرویس‌دهنده را بررسی کنید |
| مدل/درخواست نامعتبر است | endpoint کامل، نام مدل و پارامترهای پشتیبانی‌شده سرویس را بررسی کنید |
| `response_truncated` | پاسخ به سقف توکن رسیده؛ خروجی معتبر محسوب نمی‌شود |
| `budget_exhausted` | بودجه کل زمان، مراحل یا درخواست‌ها تمام شده؛ لزوماً مشکل محتوای پیام نیست |
| `policy_mismatch` | مدل برچسبی خلاف حساسیت انتخاب‌شده داده؛ بررسی مجدد یا تصمیم مدیر لازم است |
| پیام در مقصد نیست | دلیل DROP، Review، تکراری بودن، متن خالی یا خطای ارسال را از لاگ تفکیک کنید |

برای گزارش خطا، خطوط همان پیام همراه با دلیل و مرحله را ارسال کنید؛ توکن، کلید API، رشته نشست و محتوای خصوصی نامرتبط را حذف کنید.

<a id="operations"></a>
## استقرار، پشتیبان و پاک‌سازی

### Railway

از [راهنمای کامل Railway](docs/railway.md) استفاده کنید. خلاصه تنظیمات: Dockerfile ریشه پروژه، یک سرویس دائمی، Volume روی `/data`، دیتابیس `sqlite:////data/forwarder.db`، نشست `/data/forwarder_session`، لاگ کنسول و ورود با نشست صادرشده. دامنه و healthcheck وب لازم نیست، چون برنامه endpoint HTTP ندارد. جزئیات Restart و پشتیبان در راهنمای جدا آمده است.

### cPanel

قبل از نصب، مجاز بودن پردازش دائمی Python را از پشتیبانی تأیید کنید؛ «Setup Python App» به‌تنهایی کافی نیست. کد و اسرار خارج از `public_html` باشند. روش systemd برای سرور دارای دسترسی مدیریتی و روش Cron با قفل برای هاست مجاز در [راهنمای cPanel](docs/cpanel.md) توضیح داده شده‌اند.

### پشتیبان محلی

اول برنامه و هر عامل شروع مجدد آن را متوقف کنید؛ تا پایان پردازش صبر کنید. سپس از دیتابیس، نشست و `.env` پشتیبان خصوصی بگیرید. نمونه PowerShell برای مسیرهای محلی پیش‌فرض:

```powershell
$backupPath = Join-Path $env:USERPROFILE ("forwarder-backup-" + (Get-Date -Format yyyyMMdd-HHmmss))
New-Item -ItemType Directory -Path $backupPath
Copy-Item -LiteralPath data,sessions -Destination $backupPath -Recurse
Copy-Item -LiteralPath .env -Destination $backupPath
```

اگر مسیرهای دیتابیس/نشست را عوض کرده‌اید، همان مسیرهای واقعی را پشتیبان بگیرید. پشتیبان حاوی دسترسی حساب است و نباید در مخزن یا فضای عمومی قرار بگیرد. کپی تنها فایل SQLite هنگام نوشتن فعال، روش مطمئنی برای پشتیبان نیست.

### آپدیت و حذف فایل‌ها

پیش از آپدیت پشتیبان بگیرید، کد و وابستگی‌ها را به‌روز کنید و `.env`، داده‌ها و نشست را نگه دارید. بازگشت کد و بازیابی دیتابیس دو عملیات جدا هستند.

| فایل/پوشه | پیامد حذف |
|---|---|
| `__pycache__`، `.pytest_cache`، `.ruff_cache` | دوباره ساخته می‌شوند؛ کد و تنظیمات را نگه نمی‌دارند |
| `logs/` | لاگ‌ها دوباره ساخته می‌شوند، اما سابقه عیب‌یابی پاک می‌شود؛ هنگام توقف برنامه پاک کنید |
| `data/forwarder.db` | تنظیمات، تاریخچه، جلوگیری از تکرار و صف بررسی از دست می‌روند؛ ساخت فایل تازه آن‌ها را برنمی‌گرداند |
| `sessions/*.session` | ورود ذخیره‌شده و کش حساب حذف می‌شود؛ ورود دوباره یا رشته نشست معتبر لازم است |
| `sessions/railway-session.txt` | نسخه صادرشده نشست حذف می‌شود؛ نشست فعلی و متغیر سرور خودکار لغو نمی‌شوند |
| `.env` | اعتبارنامه‌ها و تنظیمات محلی حذف می‌شوند |
| `.venv` | وابستگی‌ها باید دوباره نصب شوند |

| قواعد محلی و پاک‌سازی | `rule_guard.py`، `text_normalizer.py`، `text_sanitizer.py` و `html_sanitizer.py` در services |
| صف بررسی و پیش‌نویس | `app/services/review_*.py` و `app/handlers/reviews.py`/`review_edit.py` |
| ارسال و دریافت خودکار | `app/telegram/message_sender.py`، `forward_service.py` و `auto_forward.py` |
| مدل‌ها و ثبت نتایج | `app/database/` و `app/services/forward_results.py` |

### تست و بررسی کد

ویندوز:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ruff check app scripts tests main.py
.\.venv\Scripts\python.exe -m ruff format --check app scripts tests main.py
```

لینوکس/macOS:

```bash
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
.venv/bin/python -m ruff check app scripts tests main.py
.venv/bin/python -m ruff format --check app scripts tests main.py
```

تست‌ها دیتابیس موقت مستقل دارند و ارتباط خارجی تلگرام/AI شبیه‌سازی می‌شود. موضوعات شامل دسترسی مدیر، انتقال و تکراری‌ها، بررسی و ویرایش، بودجه گارد، حفظ معنا، فایل نامعتبر، تأیید قدیمی و اعمال تنظیمات میان پیام‌هاست. در زمان تکمیل این راهنما ۳۱۵ تست پاس شده‌اند؛ این عدد گزارش یک اجرای مشخص است و با توسعه تغییر می‌کند. هشدارهای deprecation وابستگی‌ها ممکن است در Python جدیدتر دیده شوند.

برای قالب‌بندی از `ruff format` روی فایل‌های موردنظر استفاده کنید. قالب‌بندی کل مخزن ممکن است فایل‌های خارج از تغییر شما را هم تغییر دهد؛ diff را بررسی کنید.

## آزمایش عملی پس از نصب

این بخش روی تلگرام واقعی پیام ایجاد می‌کند؛ از مبدأ و مقصد آزمایشی تحت کنترل خود استفاده کنید.

۱. پاسخ `/start` و اتصال در لاگ را بررسی کنید.
۲. مبدأ و مقصد را تعیین و یک متن عادی منتقل کنید؛ متن نهایی و امضا را در مقصد ببینید.
۳. همان شناسه را دوباره برای همان مقصد انتخاب کنید؛ ارسال موفق قبلی نباید تکرار شود.
۴. AI را تنظیم کنید و یک متن قابل اصلاح را آزمایش کنید؛ نتیجه به مدل و سیاست شما وابسته است.
۵. یک مورد حل‌نشده را در `/reviews` باز کنید؛ ویرایش و بازنویسی نباید پیش از تأیید شما منتشر شوند.
۶. خروجی JSON گارد را بگیرید، حساسیت یا قانون اختصاصی را تغییر دهید، پیش‌نمایش را بخوانید و تأیید کنید؛ فایل خروجی تازه باید تغییر را داشته باشد.
۷. فایل خراب یا ناقص بفرستید؛ باید رد شود و تنظیم قبلی باقی بماند.
۸. Auto-Forward را فعال و پیام تازه ایجاد کنید؛ دریافت و ارسال را در لاگ دنبال کنید.
۹. Restart کنید؛ نشست، کانال‌ها، تنظیمات و درخواست‌های بررسی باید با حفظ دیتابیس باقی بمانند.
۱۰. با حساب خارج از `ADMIN_IDS`، دسترسی مدیریتی نباید داده شود.
